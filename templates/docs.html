Premium Hub PayHub API Documentation

Direct Pay + Wallet Topup + Automatic Payment Confirmation

1. Configuration

The bot expects these three PayHub settings:

PAYMENT_BASE_URL={{ base }}
PAYMENT_API_KEY=pk_live_xxxx
PAYMENT_WEBHOOK_SECRET=whsec_xxxx

The bot sends the API key using:

X-API-Key: pk_live_xxxx
Content-Type: application/json

2. Create Invoice API

POST {{ base }}/api/v1/invoice

Headers

X-API-Key: YOUR_PAYMENT_API_KEY
Content-Type: application/json

Request

{
  "telegram_id": "123456789",
  "amount": "10.5",
  "currency": "USDT"
}

Recommended response

{
  "ok": true,
  "invoice_id": "INV-ABC123",
  "uid": "123456789",
  "amount": "10.5",
  "currency": "USDT",
  "status": "PENDING"
}

Accepted invoice ID aliases:

invoice_id
invoiceId
invoice_no

Accepted UID aliases:

uid
binance_uid
binanceUid
pay_uid
payment_uid
wallet_id
walletId

3. Verify Payment API

This is used when the customer sends the Binance TX / Order ID to the Telegram bot.

POST {{ base }}/api/v1/verify

Headers

X-API-Key: YOUR_PAYMENT_API_KEY
Content-Type: application/json

The bot may try the entered ID using these field conventions.

Attempt 1 — preferred

{
  "invoice_id": "INV-ABC123",
  "order_id": "P_ABC123456"
}

Attempt 2

{
  "invoice_id": "INV-ABC123",
  "txid": "P_ABC123456"
}

Attempt 3

{
  "invoice_id": "INV-ABC123",
  "tx_id": "P_ABC123456"
}

Successful verification response

{
  "ok": true,
  "invoice_id": "INV-ABC123",
  "status": "PAID",
  "txid": "P_ABC123456",
  "network": "BINANCE_PAY"
}

Successful statuses:

PAID
SUCCESS
COMPLETED
CONFIRMED

The bot can also recognize:

{ "paid": true }
{ "verified": true }
{ "confirmed": true }

These states must not be treated as paid:

FAILED
INVALID
MISMATCH
WRONG_INVOICE
NOT_FOUND
PENDING
UNPAID
EXPIRED
CANCELLED
CANCELED

4. Automatic Webhook

Recommended bot webhook URL:

https://YOUR-BOT-DOMAIN/api/v1/payments/webhook

The current bot also accepts:

POST /webhook
POST /api/v1/payments/webhook
POST /ipn

Webhook headers

X-Webhook-Secret: YOUR_PAYMENT_WEBHOOK_SECRET
Content-Type: application/json

If the secret is wrong, the bot returns:

401 invalid-secret

5. PAYMENT_PAID Webhook

Recommended payload

{
  "event": "PAYMENT_PAID",
  "invoice_id": "INV-ABC123",
  "status": "PAID",
  "txid": "P_ABC123456",
  "amount": "10.5",
  "currency": "USDT"
}

Transaction ID aliases:

txid
order_id
tx_id

Success response

HTTP 200

ok

Other possible responses:

ignored
unknown-invoice
not-paid
duplicate

6. Direct Pay Flow

Customer selects product
        ↓
Bot creates local order
Status = PENDING_PAYMENT
        ↓
Bot → PayHub
POST /api/v1/invoice
        ↓
PayHub returns
invoice_id + Binance UID
        ↓
Bot saves invoice
payment_kind = order
reference_id = ORD-XXXXXXXXXX
        ↓
Customer sends exact payment
        ↓
Payment can be confirmed by:
A) PayHub webhook
or
B) Customer submits Binance TX / Order ID
        ↓
Bot verifies payment
        ↓
Invoice marked PAID
        ↓
Order marked PAID
        ↓
Product stock is reserved
        ↓
Product delivered automatically
        ↓
Order = COMPLETED

Example:

payment_kind = order
reference_id = ORD-91A2B3C4D5

8. Idempotency / Duplicate Protection

The bot stores processed payment markers using:

invoice_id + transaction/order ID
  • Repeated webhook delivery must not credit the wallet twice.
  • Repeated TX verification must not complete the same purchase twice.
  • PayHub may safely retry a webhook when network delivery is uncertain.
  • PayHub should always send a stable unique transaction/order ID.

10. HTTP Error Handling

For outbound PayHub APIs, any HTTP status >= 400 is considered an API error.

The bot looks for an error message in:

message
error
detail

Recommended error response:

{
  "ok": false,
  "error": "Payment not found"
}

11. Security Requirements

  1. Always use HTTPS for PAYMENT_BASE_URL.
  2. Keep PAYMENT_API_KEY private.
  3. Keep PAYMENT_WEBHOOK_SECRET private.
  4. PayHub must include X-Webhook-Secret on every webhook.
  5. Never expose the API key or webhook secret to Telegram customers.
  6. Use a unique PayHub transaction/order ID for every payment.
  7. Do not treat PENDING or UNPAID as successful.
  8. Retry webhook requests when the bot does not return HTTP 200.
Current V25.5 authentication uses a shared webhook-secret header, not an HMAC body signature.

12. cURL Examples

curl -X POST "{{ base }}/api/v1/invoice" \
  -H "X-API-Key: pk_live_xxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "telegram_id":"123456789",
    "amount":"10",
    "currency":"USDT"
  }'

curl -X POST "{{ base }}/api/v1/verify" \
  -H "X-API-Key: pk_live_xxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "invoice_id":"INV-ABC123",
    "order_id":"P_ABC123456"
  }'

curl -X POST "https://YOUR-BOT-DOMAIN/api/v1/payments/webhook" \

  -d '{

  }'

PAYMENT_BASE_URL
